# 动作库数据契约

动作库存放从第三方教学视频沉淀的动作条目与示范片段，供 `fitness-plan` 等处方 Skill 在出每日处方和讲解动作时引用。它是**示范与要点来源**，不拥有训练事实：重量、组次、RPE 与是否采用某动作，仍以当前计划、执行基准和复盘为准。

动作库不是必选组件。库不存在时所有读取方静默跳过，不报错、不拿示例数据冒充条目。

## 位置与写入纪律

固定分区：`个人训练系统/动作库`，首次写入时创建。根目录解析优先级与训练 Skill 相同：本次用户明确路径 → `系统/keshig-system.json` → 环境变量 `KESHIG_FITNESS_HOME`；未解析到系统时停止写入并说明缺失项。写入前运行 `training-system` 的 `check-path --path <目标>`；动作库必须位于源码与整个已安装 `skills/` 目录之外。

库内引用一律使用系统内相对路径，不依赖固定盘符。示范片段的原始导出文件留在 video-reader-mcp 的片段目录，由用户管理，Agent 不擅自删除。

## 目录结构

```
个人训练系统/动作库/
├── INDEX.json        # 机器索引，按动作名与别名检索
├── 片段/             # 示范片段 MP4，库自持副本
└── <动作名>.md       # 每个动作一份条目
```

## 条目（<动作名>.md）

按以下顺序组织，缺项写「未知」，不编造：

1. **动作名与别名**：主名用用户惯称，别名收录视频中的其他叫法。
2. **目标肌群与动作模式**：与计划书的固定肌群标注口径一致。
3. **器械与场地**。
4. **要点列表**：每条单独标注来源——`[原话]` 来自逐字稿、`[画面]` 经关键帧或指定时间画面核对、`[归纳]` 是 Agent 整理。归纳不得写成原话。
5. **常见错误**：同样逐条标注来源。
6. **适用边界与禁忌**：作者声明与 Agent 归纳分开；涉及伤病与异常体征只写「这要医生看」。
7. **示范片段**：时间段（起止秒）、库内相对路径（`片段/xxx.mp4`）、一句话说明该段展示什么。
8. **来源**：平台、链接、视频标题、上传者与画面讲者（分别记录）、转写方式（人工字幕／平台 AI／本地 ASR）、录入日期。
9. **核对状态**：`已核对` 表示画面与文字一致；只读了逐字稿的条目保持 `未核对`。

## 索引（INDEX.json）

```json
{
  "schema": 1,
  "movements": {
    "<动作名>": {
      "file": "<动作名>.md",
      "aliases": ["别名"],
      "muscles": ["胸", "三头"],
      "equipment": "哑铃",
      "clips": [{ "file": "片段/xxx.mp4", "start": 20, "end": 55, "label": "全程示范" }],
      "source_url": "https://...",
      "reviewed": false,
      "updated": "2026-11-12"
    }
  }
}
```

索引只放检索字段；要点与解释以条目 Markdown 为准。写入条目必须同事更新索引，两处动作名一致。

## 片段规则

- 经 video-reader-mcp 的 `extract_video_clips` 按用户确认的时间段导出（每次 1–5 段、每段 1–180 秒），再把导出的 MP4 **复制**进 `片段/` 作为库自持副本；条目只引用库内副本的相对路径。
- 片段含平台版权内容，只在用户本机使用：不进公开仓库、不上传、不再分发。`extract_video_clips` 失败时不能声称片段已生成，条目保持无片段状态。
- 片段丢失或路径失效时，可按来源链接与原时间段重新导出；不静默替换为其他视频的画面。

## 多来源与冲突

同一动作收到新视频时更新同一词条：追加来源、补充要点，不新建重复条目。不同作者说法冲突时并排保留并各自标注来源，不替用户裁决；影响训练安全的冲突在对话中说明。

## 回放边界

仓库与 Skill 不提供播放器。对话内即时展示优先使用关键帧图片；用户要求看片段时，用系统默认播放器打开库内副本，或直接给出路径。
