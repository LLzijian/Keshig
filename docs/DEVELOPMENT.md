# 开发、自己使用与发布

开发者也通过安装后的 Keshig 使用个人系统。源码目录只放代码、公开知识和独立构造的虚构测试数据；个人档案、计划、复盘、饮食、照片、数据库、缓存和备份放在另一个目录。个人目录不能位于源码或已安装的 `skills/` 中。

## 开始开发

在仓库运行：

```text
python tools/setup_dev.py
```

它只为当前仓库启用 `.githooks`，并在本地 Git 配置记录当前 Python。已有自定义 hooks 时保留原设置并说明如何串接；不会覆盖。Git 提交前检查暂存区，推送前检查本地历史和本次推送的版本。换电脑或 Python 位置后重新运行。

hooks 属于本地保护，可被 `--no-verify` 或修改配置绕过；`.gitignore` 与规则扫描也不能识别任意文字里的健康信息。不要在源码目录做真实使用；公开问题与测试用虚构资料复现，不从个人记录复制后再脱敏。

## 修改后验证

```text
python tools/validate_bundle.py
python tools/privacy_check.py --mode staged
python tools/privacy_check.py --mode history
```

整包校验包含独立临时目录的安装、训练计划与营养示例校验、复盘文件读取、升级保留、迁移、数据路径隔离、设备协议与配置失败后的恢复。测试不需要真实凭据，也不访问用户个人系统。修改过的 Skill 需要重新安装，才会成为日常使用版本；先检查漂移，再备份更新。

## 自己使用

1. 修改并验证源码。
2. 安装到 Agent 真正使用的技能主目录。Codex 默认使用 `~/.agents/skills`；已有指向该目录的入口联接保留，其他任意联接目标仍拒绝安装。
3. 在源码之外建立个人系统，之后只读写该目录。
4. 更新用 `tools/upgrade.py`，先检查再 `--apply`；保留个人文件、旧 Skill 备份与私人适配器。

不要把个人机器路径写回公开配置、文档或测试。个人位置由本机系统配置和 `KESHIG_FITNESS_HOME` 指定；密钥由系统凭据管理器管理。

## 发布检查

```text
python tools/build_release.py
```

默认在被忽略的 `release-output/` 生成源码 ZIP，不上传或发布。先检查工作区候选文件和本地全部可达 Git 历史，再按公开目录与文件类型白名单打包；个人目录、二进制照片、数据库、凭据文件及异常链接会阻止发布。旧文件从当前目录删除后，其历史内容仍参与检查。文件内容检查只报告路径和问题类别，不回显疑似凭据。

新增公开文件类型时，先审查数据边界，再更新 `tools/privacy_check.py` 的白名单与测试。发布包包含当前工作区内容；发布前运行整包校验并人工检查改动。CI 是上传后的复核，不能替代本地推送前检查。
