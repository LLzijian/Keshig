# 新手搭建个人健身系统指南

这份指南写给第一次接触本地 Agent、不会写代码，也没有系统训练记录的人。你不需要理解脚本、JSON 或 Skill 名称；正常情况，只要有一台电脑和一个能读写本地文件的 AI Agent，就可以让 AI 帮你完成安装和搭建。

## 一、你最后会得到什么

一套保存在自己电脑里的个人健身系统，主要包括：

- 一份根据你的目标、时间、器械和身体情况生成的 Markdown 训练计划书；
- 一份结构化计划 JSON，供 Agent 读取当前处方；
- 每次训练后的复盘记录与下一场明确安排；
- 停训、漏练或状态变化后的接回方案；
- 营养目标、餐食确认记录与两周趋势复盘；
- 一个可以整体复制到新电脑的本地文件夹。

它不是一个替你训练的 App，也没有网页界面。你负责真实训练和如实反馈，Agent 负责整理信息、生成计划、记录复盘和更新下一次安排。产品边界见 [产品定义](PRODUCT.md)。

## 二、开始前准备

你需要：

1. 一台 Windows、macOS 或 Linux 电脑；
2. 一个能读取和修改本地文件的 AI Agent，例如 Claude Code、Codex，或支持 Agent Skill 的兼容工具；
3. Python 3.10 或更新版本；
4. 一个准备存放个人训练系统的空文件夹，例如在「文档」中新建「我的健身系统」。

可选：如果你想把华为手环的睡眠、静息心率、HRV、步数和运动记录接进来，还需要上游 VitalDock 与 Intervals.icu 的 API key。不配置不影响训练和营养系统。

不知道电脑有没有 Python，可以把这句话交给 Agent：

```text
请检查这台电脑是否安装了 Python 3.10 或更新版本。如果没有，请告诉我最简单、安全的安装方法；安装完成后再继续，不要跳过版本检查。
```

## 三、让 Agent 完成安装

把下面这段话发给 Agent：

```text
请阅读 Keshig 仓库的 README 和 AGENTS.md，检查 Python 版本，安装全部 Keshig Skills，并运行项目自带的验证。不要覆盖我电脑上已有的同名 Skill；如果发现旧版本，先告诉我备份和升级方案。完成后告诉我安装位置、验证结果，以及我下一步只需要说什么。
```

Agent 应完成：

1. 确认 Python 版本；
2. 运行 `python tools/install.py --platform codex`（Claude Code 用 `claude`，其他兼容 Agent 用 `agents`）；
3. 核对安装输出里的 `KESHIG_FITNESS_INSTALL: PASS` 与 `KESHIG_FITNESS_VERIFY: PASS`；
4. 明确告诉你安装是否成功，而不是只说「应该可以」。

安装器会把 Skill 放进对应 Agent 的 `skills/` 目录，把安装记录放在 `.fitness/`，不会改你的个人资料。

## 四、开始建立我的健身系统

安装成功后，新开一个对话，让 Agent 重新加载 Skill，然后只说：

```text
开始建立我的健身系统。
```

正常情况下，Agent 会先问你三件事：

- 主要目标是增肌、减脂、提升力量，还是综合改善；
- 你是完全新手、练过一段时间，还是已有稳定计划；
- 有没有疼痛、旧伤、术后恢复或其他会影响训练的情况。

如果 Agent 一上来让你自己找脚本、填 JSON 或研究 README，说明它没有按新手入口工作。先新开对话再说一次「开始建立我的健身系统」。

### 建档会问什么

随后 Agent 会继续了解真正影响计划的信息：

- 性别、身高、体重、年龄（年龄可不说）；
- 每周能训练几次、每次多长时间；
- 在家还是健身房，有哪些器械；
- 最近是否训练过，过去做过哪些动作；
- 睡眠、疲劳、工作压力和恢复情况；
- 目前可靠的动作重量和训练记录；
- 饮食限制、过敏、是否记录热量。

不知道的内容直接说「不知道」。不要为了让资料看起来完整而猜重量、猜次数或隐瞒疼痛。未知字段会标成「待填写」或「待校准」，不会变成假数据。

## 五、可选：接入华为健康数据

如果想让 Agent 看到设备测到的睡眠、静息心率、HRV、步数和运动记录，可以在这时说：

```text
我想接入华为健康数据，请告诉我需要准备什么。
```

链路是：

```text
华为运动健康 → Intervals.icu（本人 API key）→ 上游 VitalDock 只读 CLI → Keshig 适配器
```

要点：

- VitalDock 是一个独立的上游项目，Keshig **不复制**它的源码，也不写它的目录，只以子进程读取它的输出；
- API key 保存在你自己的电脑和账号里，**不要**发到公开仓库、聊天记录或截图里；
- 上游路径用环境变量 `VITALDOCK_HOME` 指定；Agent 也可以探测仓库同级目录下的 `vitaldock/`、`VitalDock/`、`BioDeviceData/`；
- 设备数据和你的手记会**分表保存、并排对照**，不会自动合并；
- 当天没有记录就是「还没同步」，不会写成 0。

不想配置就跳过，训练、复盘和营养系统完全不受影响。

## 六、完成重量校准

如果你没有可靠的动作重量，系统不应该直接编一个数，也不应该让你随便猜。

Agent 会带你用较轻重量试做，并根据以下反馈找到起始重量：

- 实际使用的重量；
- 完成的次数；
- 做完后大约还能再做几次；
- 动作是否稳定；
- 有没有疼痛或异常不适；
- 主观感觉偏轻、合适还是偏重。

校准不是测极限。新手第一次训练的重点是学会动作，找到可以稳定重复的起点。

## 七、确认第一版正式计划

建档和必要的校准完成后，Agent 应先展示计划依据，再生成正式文件。你至少要看懂：

- 计划的主要目标与周期长度；
- 每周训练几次；
- 每个训练日练什么；
- 第一次训练做哪些动作；
- 时间不足时怎么缩短；
- 出现什么情况应该停止；
- 哪些重量已经确认，哪些还需要现场校准。

计划以两个文件保存：一份 Markdown 计划书给你读，一份 JSON 给 Agent 读。两者必须来自同一份数据；如果你看到它们不一致，先让 Agent 修正。

## 八、日常怎么用

不需要每天操作文件，也不需要记住 Skill 名称，直接用自然语言说。

### 训练前

```text
我今天练什么？请根据当前计划告诉我动作、重量、组数、次数、休息时间和时间不足版本。
```

### 训练后

```text
我练完了。实际重量、次数、余力、疼痛和主观感受是……
请完成复盘，并告诉我下一次的明确安排。
```

### 一周复盘

```text
帮我复盘这一周的训练。区分已经验证的事实和还不确定的判断，先告诉我是否需要调整计划，再更新下周安排。
```

### 停训或连续漏练

```text
我已经一周没有训练了，请不要让我补课。先判断我现在适合正常接回、降级训练还是最低任务，再生成未来 7 天的接回安排。
```

### 想提高某个力量动作

```text
我想提高卧推。请先读取我的当前完整计划和近期训练，不要让专项周期与原计划冲突；需要修改原计划时先展示差异，等我确认。
```

### 饮食

```text
帮我建立饮食目标。先问我用哪种方法，不要拿通用表格冒充我的口径。
```

每次训练后尽量提供真实的重量、组数、次数、余力、疼痛和主观感受。信息不完整时，Agent 应该追问；你不记得的项可以直接说「不记得」，它不会把猜测写成事实。

## 九、迁移到新电脑

迁移时不要只复制计划书或某个 JSON。正确方法：

1. 复制整个个人训练系统根目录（里面有 `系统/keshig-system.json` 和各分区）；
2. 在新电脑安装 Python 和本地 Agent；
3. 在新电脑重新安装最新版 Keshig Skills；
4. 把复制过来的目录交给 Agent，说明这是迁移后的当前位置；
5. 让 Agent 运行 `doctor`、`validate`，必要时运行 `upgrade` 迁移旧绝对路径；
6. 确认当前计划、执行基准、复盘和营养记录都能读到。

可以直接对新电脑的 Agent 说：

```text
这是我从旧电脑完整复制过来的 Keshig 训练系统。请安装或检查最新 Skills，以当前目录为准运行 doctor 和 validate，修复旧绝对路径，但不要覆盖我的计划、复盘、状态档案、营养记录和私人资料。
```

目录换盘符、改名字或放进带中文和空格的路径都可以，但必须整套目录一起移动。系统只使用相对路径，不依赖固定盘符。

## 十、常见问题

### 1. AI 说找不到新安装的 Skill

先新建一个对话。如果仍然找不到，让 Agent 检查 Skill 是否安装到了当前 Agent 实际使用的目录，而不是重复下载项目。

### 2. 安装时提示同名 Skill 已存在

不要直接强制覆盖。先让 Agent 运行 `--verify` 漂移检查，说明哪些文件缺失、被修改或额外出现，再决定是否用 `--force`。强制安装会把旧 Skill 备份到 `.fitness/backups/`，不会把备份留在活动 `skills/` 目录里。

### 3. 计划书和 JSON 对不上

让 Agent 检查两者是否来自同一次生成，并运行 `validate_plan.py`。不要手工改 JSON 让数字看起来一致。

### 4. 系统显示「待建档」或用的是示例数据

示例只代表初始化成功。告诉 Agent 完成正式建档、校准和计划生成，并把正式计划写入当前周期与执行基准。

### 5. 换了电脑后读不到以前的记录

通常是因为只复制了部分文件。让 Agent 对完整系统目录运行 `doctor` 和 `upgrade`，把旧绝对路径迁移到当前位置；不要重新初始化覆盖原目录。

### 6. 设备数据查不到

先让 Agent 运行 `python device/vitaldock_client.py selftest`，确认上游路径；再运行 `check --day <日期>` 看退出码和错误体。认证失败、限流、未授权都是上游原样透传的错误，不会伪造数据。

## 十一、安全边界

这套系统提供一般训练规划、记录和调整支持，**不代替医疗诊断、康复治疗或用药建议**。

出现胸部异常不适、晕厥、异常气短、锐痛、麻木、放射痛、明显功能受限或症状持续加重时，应停止普通高强度训练并寻求合适的专业评估。疼痛不是「意志力不够」，也不能只用训练强度评分解释。

遇到伤病、用药、异常体征，Agent 只会说「这要医生看」，不会诊断、开药或给出替代治疗方案。

个人数据只保存在你自己的电脑上。仓库不收集、不上传、不发布任何个人资料；API key、token 和照片也不应进入公开仓库或公开对话。

## 十二、只记住这三句话

1. 安装后说：`开始建立我的健身系统。`
2. 训练前说：`我今天练什么？`
3. 训练后说：`我练完了，这是我的真实训练数据，请复盘并更新下一次安排。`

你负责真实执行，Agent 负责把每一次真实训练变成下一次更明确的行动。

升级系统见 [升级说明](UPGRADE.md)；公开来源学习示例见 [知识库示例](KNOWLEDGE-EXAMPLE-REVIEW.md)。
